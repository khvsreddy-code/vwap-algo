# Replay / backtest marker fix v9.4.24

## Fixed the marker-stacking bug

The previous version converted trade timestamps to Unix seconds correctly, but
the browser chart could retain a candle-series state from an earlier replay
window. The chart now re-sends the complete historical candle payload whenever
the component receives a payload. This keeps candle timestamps and trade-marker
timestamps in the same dataset.

Trade markers are now generated by:
- converting both candle timestamps and trade timestamps through UTC epoch seconds;
- snapping each event to the nearest actual candle in the loaded FYERS dataset;
- assigning a unique marker id;
- sorting chronologically.

## Fixed same-candle replay exits

If replay currently ends on the candle that generated an entry, the replay no
longer fabricates an END exit on that same candle. An exit can only occur on a
later candle.

## No random data

The full backtest and replay continue to use the exact historical dataframe
loaded from FYERS on the page.
